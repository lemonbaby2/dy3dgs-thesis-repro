## 二、环境修复（关键障碍）

原本两个训练环境**完全无法启动**：

```
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xb4 in position 3
  File "...\lib\site.py", line 188, in addpackage
```

**根因**：`D:\GS_Envs\gaussian_3dgs\Lib\site-packages\easy-install.pth` 与
`D:\GS_Envs\gaussian_4dgs\Lib\site-packages\easy-install.pth` 是 setuptools 以 **GBK** 写入的，
内容指向 `d:\达闼机器人slam与4dgs复现交付\src\official\...\submodules\{diff-gaussian-rasterization, simple-knn, fused-ssim}`；
而 Python 3 的 `site.py` 按 **UTF-8** 读取 `.pth`，遇到中文路径字节即抛异常，导致解释器启动失败。

**处置**：备份为 `easy-install.pth.bak_gbk`，按 GBK 解码后以 UTF-8 重写（内容不变，仅编码）。

修复后验证：

| 环境 | torch | 光栅化扩展 | simple_knn |
|---|---|---|---|
| `D:\GS_Envs\gaussian_3dgs` | 2.1.2 | ✅ diff_gaussian_rasterization | ✅ |
| `D:\GS_Envs\gaussian_4dgs` | 2.1.2 | ✅ depth-diff-gaussian-rasterization | ✅ |

> 这是本次最有价值的一条排障记录：**中文路径 + GBK 的 .pth 会让 venv 静默报废**，报错栈还指到 base 环境的 `site.py`，极易误判为 base 环境坏了。

### GPU 算力约束

| 卡 | 显存 | compute capability | torch 2.1.2 支持 |
|---|---|---|---|
| RTX 4060 | 8188 MiB | 8.9 | ✅ 可用 |
| RTX 5060 Ti | 16311 MiB | 12.0（sm_120） | ❌ 不支持 |

所以官方 3DGS/4DGS 复现只能落在 **4060** 上。大显存卡要跑，必须为 sm_120 重编译光栅化扩展并升级 torch。

## 三、训练系统启动验证

### 3.1 官方 3DGS 管线（RTX 4060）

```bash
cd D:/GS_Repro/src/official/gaussian-splatting
CUDA_VISIBLE_DEVICES=0 D:/GS_Envs/gaussian_3dgs/Scripts/python.exe train.py \
  -s D:/GS_Repro/datasets/nerf_synthetic/lego_white_rgb \
  -m D:/GS_Repro/outputs/3dgs/verify_1000 \
  --eval --iterations 1000 --test_iterations 1000 --save_iterations 1000 --quiet -w
```

结果：1000 次迭代 **31 秒**完成（59.9 it/s），产出 `point_cloud.ply` 5.6 MB，无报错。

> 速度随迭代下降，是高斯增密（densification）后每步光栅化代价上升的正常表现。

## 四、三次重复验证

### 4.1 合成动态场景：3 配置 × 3 种子 = 9 次

脚本 `run_multiseed.py`，种子 `[0,1,2]`，超参与原实验完全一致（2500 iter / 5000 基元）。

**确定性核验**：seed=0 的 `naive` 配置重跑结果为 22.585 / 30.777 / 0.0816，与 2026-11-11 上午首次运行的 `metrics.json` **完全一致**，证明该实现是可确定复现的。

seed0 三配置已出结果（静态区 PSNR / 残影）：

| 配置 | 静态区 PSNR | 残影残差 |
|---|---|---|
| `naive` | 30.777 | 0.0816 |
| `no-dyn-data` | 31.444 | 0.0642 |
| `dyn-mask` | **34.351** | **0.0048** |

注意 `dyn-mask` 的**全图** PSNR（21.10）是三配置里最低的，因为它主动放弃拟合动态区 —— 只看全图 PSNR 会得出完全相反的结论。

完整跨种子统计与 5 项稳定性判定见 `verification/README.md`。

### 4.2 官方 3DGS：3 次 7000 迭代复跑

同一数据、同一参数、连续三次训练，用 `render.py` + `metrics.py` 分别评测，量化训练过程的重复性误差。

| 运行 | PSNR (dB) | SSIM | LPIPS |
|---|---|---|---|
| r1 | 34.8659 | 0.97970 | 0.02222 |
| r2 | 34.8311 | 0.97945 | 0.02257 |
| r3 | 34.8366 | 0.97946 | 0.02249 |
| **均值 ± 标准差** | **34.8445 ± 0.0187** | 0.979539 ± 0.000142 | 0.022427 ± 0.000181 |

极差 0.0347 dB，相对波动 0.054%。

> 这部分的意义：三次结果的 PSNR 标准差就是"这套代码在当前硬件上的固有波动"。低于这个量级的差异，不应解释为方法改进。
>
> 具体地：**本机上 < 0.02 dB 的 PSNR 差异与噪声无法区分**。作为对照，合成场景 seed0 的静态区提升是 +3.574 dB，是该波动的 **191 倍**，属于不可争议的量级差异。
>
> 波动来源是 GPU 非确定性（光栅化原子累加顺序、`simple_knn` 距离排序、cuDNN benchmark）与数据加载顺序，固定随机种子也无法完全消除。
>
> 该 34.84 dB 是 7000 迭代 checkpoint 的成绩，与 30000 迭代的 37.41 dB 不矛盾，但**不可横向比较**。
